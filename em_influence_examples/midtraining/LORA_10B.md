# LoRA continued midtraining on 10B input tokens

The 2026-11-05 request authorizes a fresh 10B non-padding-input-token run, ten times the previous 1B budget. The recipe is `lora_10pct.json`: the same pinned OLMo3 stage1 initialization, dataset revision, seed and source proportions; global batch 128 (8 GPUs × microbatch 2 × accumulation 8), LR 1e-4, betas (0.9, 0.95), BF16 autocast, FlashAttention 2, fused linear cross-entropy, fused AdamW and nonreentrant checkpointing. The token-based scheduler warms up over 3% of the new 10B budget and then decays linearly.

Launch in a persistent tmux session with `.venv-speedrun/bin/python -u em_influence/scripts/run_midtrain_lora.py --config em_influence_examples/midtraining/lora_10pct.json --run NEW_DIRECTORY`. The launcher records the explicit run authorization, freezes source files, prepares new unique windows, validates a production-model preflight and interrupted recovery against an independent replay, and then starts full training from fresh base weights. Any failed stage stops the pipeline. It does not run SFT or evaluation.

Preparation reuses the pinned inventory from the earlier experiment but writes a new run-local sample, without replacing historical data or approval files. It samples windows without replacement within each source, uses largest-remainder source quotas and a fixed seeded shuffle, verifies HTTP ETags and byte ranges, checks token IDs, and records window and token-file checksums. The plan has 6% extra token slots for existing padding, and must cover the actual 10B non-padding-token target before training can start. Download work is bounded rather than queuing a future for every window.

The run contains `config.json`, `training_approval.json`, frozen `source/`, `data/full/manifest.json`, `data_audit.json`, `validation/`, `full/`, command files and logs. Each trainer checkpoint is atomic and contains adapters, optimizer, scheduler, RNG and exact data position. The latest two full-run checkpoints are retained; older checkpoints within this new run are pruned only after a complete replacement exists. Validation artifacts remain available. Full training stops after the first complete optimizer window reaching 10B input tokens, reloads the saved adapter and verifies ordered data coverage.

`status.json` records pipeline stages. For durable detailed observation, run `.venv-speedrun/bin/python em_influence/scripts/observe_midtrain_lora.py --run RUN_DIRECTORY --session PIPELINE_TMUX_SESSION` in a separate tmux session. It writes `live_status.json` with preparation counts, validation phase, training progress and a throughput-based ETA once training measurements exist. It never starts or restarts training.

For recovery, use the run's frozen `source/train_midtrain.py`, original config, environment and eight-rank layout, adding `--resume COMPLETE_CHECKPOINT --output NEW_DIRECTORY --approval-file RUN_DIRECTORY/training_approval.json --preflight-report RUN_DIRECTORY/validation/preflight/result.json --resume-verification RUN_DIRECTORY/validation/resume_verification.json --mode full`. Keep the same training source and dependencies.
