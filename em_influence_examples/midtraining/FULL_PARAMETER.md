# Speedrun mid-training full-parameter

The 2026-10-28 request authorizes preflight, checkpoint resume validation, a 39-step throughput pilot, and a fresh full-budget run on GPUs 0–7. Do not run SFT or evaluations in this pipeline.

The prepared sample is reused read-only from `/mnt/ssd-1/ryvaan/em_influence/midtrain_lora/full`. Its manifest hash must equal the completed baseline's `result.json`. The updated 2026-11-05 recipe uses 128 sequences per optimizer step (4x the previous 32): eight GPUs × microbatch 2 × accumulation 8. Each rank receives two consecutive sequences starting at `step*128 + micro*8*2 + rank*2`. On the existing full manifest, the 1B target ends at step 961: 1,000,949,094 input tokens and 1,000,826,892 loss tokens. The launcher computes this prefix from the manifest and configured batch size. This retains 8192-token windows, EOS, dense cross-document attention, PAD target masking and all-text causal loss.

Use `.venv-speedrun/bin/python em_influence/scripts/run_midtrain_full.py --config em_influence_examples/midtraining/full_parameter_1pct.json --run NEW_DIRECTORY` inside tmux. The pipeline never overwrites a run. It stops on any failed gate; the full run starts from the pinned stage1 model with the 1B-token schedule, never the pilot model.

FSDP FULL_SHARD wraps Olmo3 decoder layers. BF16 forward/backward compute uses FP32 master parameters, AdamW states and gradient reductions. Each microbatch synchronizes gradients to avoid materializing unsharded accumulated gradients. Both full-parameter and LoRA training use LR 1e-4, actual-token linear decay, 3% warmup, fused AdamW with betas (0.9, 0.95), epsilon 1e-8, weight decay 0.01 and clipping 1.0. Both loops use FlashAttention 2, BF16 autocast and nonreentrant activation checkpointing. The fused linear cross-entropy forward in `midtrain_optimizations.py`, adapted from `/home/gpaulo/midtrain-opt-20261104/`, avoids materializing vocabulary logits and divides summed causal CE by actual global target tokens, including distributed gradient averaging. All-PAD microbatches contribute zero loss. LoRA keeps its frozen BF16 base and PEFT adapter parameter policy; adapter computation runs under BF16 autocast.

Recoverable checkpoints contain model shards and local AdamW shards for all eight ranks, scheduler, Python/NumPy/CPU/CUDA RNG, exact ordered sample coverage, step and input/loss counters. Saving uses a `.partial` directory, file SHA256 hashes, `complete.json`, and atomic rename. PyTorch 2.7.1 LOCAL_STATE_DICT CPU offload triggers a ShardedTensor requires_grad metadata error; serialization instead copies CUDA storage through torch.save. Restoring requires the same eight-rank wrapping and optimizer layout. The preflight resumes in a new process and compares the next step against an uninterrupted checkpoint across every model shard and optimizer state. Restored shard hashes and optimizer states are checked exactly before continuing. Post-step maximum AND mean model/optimizer differences must be within four times independent uninterrupted BF16 replay variation, with FP32 roundoff floors of 1e-7 maximum and 1e-12 mean. The initial stricter elementwise test failed; that failure is retained in the run artifacts. The independent replay calibrates numerical variation without skipping exact state restoration or coverage checks.
